# 결제

## 구현 상태

결제 endpoint, PG 연동, 결제 상태 전이는 아직 구현되지 않았음.
현재 주문은 `PENDING_PAYMENT`로 생성되고, 재고 예약은 결제 승인·실패 처리와 연결되지 않았음.

## 초기 결제 방식

초기 결제 수단은 수동 계좌이체만 제공.
관리자가 실제 계좌 입금 내역을 확인한 뒤 입금 확인 처리.
초기 범위에는 PG, 가상계좌, 고객 계좌 연동, 계좌 내역 자동 조회·자동 매칭을 포함하지 않음.
향후 카드·PG 등 다른 결제 수단을 추가할 수 있도록 결제수단은 provider 종속 값이 아닌 확장 가능한 코드로 관리.

## 입금 확인 상태

입금 확인의 전권은 운영자에게 있으며, 실제 입금 내역을 확인한 운영자가 누적 입금 확인 금액을 등록.
고객은 주문 조회에서 다음 상태를 확인.

| 결제 상태 | 의미 | 주문·재고 처리 |
| --- | --- | --- |
| `WAITING_FOR_DEPOSIT` | 운영자의 입금 확인 전 | 주문 `PENDING_PAYMENT`, 재고 예약 유지 |
| `PARTIAL_PAYMENT_REVIEW_REQUIRED` | 확인 금액이 주문 총액보다 적음 | 주문 `PENDING_PAYMENT`, 재고 예약 유지, 운영자가 전화로 후속 처리 |
| `PAYMENT_CONFIRMED` | 누적 확인 금액이 주문 총액과 일치 | 주문 `PAID`, 재고 예약 확정 |

운영자 입금 확인은 `ORDER_WRITE` 권한으로 제한.
확인 금액과 상태 변경은 처리자·시각과 함께 별도 이력으로 남기고 운영 변경 감사 로그도 기록.
주문 총액을 넘는 금액 등록은 거절하며, 초과 입금 처리는 운영자가 별도로 연락해 처리.
부분 입금은 별도 결제 건으로 분할 승인하지 않고 누적 확인 금액과 검토 필요 상태로 표시.

주문 생성 시 재고를 예약하는 현재 동작을 유지하며, 미입금 예약 자동 만료·해제는 초기 범위에서 수행하지 않음.
입금자명·계좌 안내 정보의 구성 및 보존 기간은 미확정.

주문 완료·재고 확정은 전액 입금 확인 트랜잭션 안에서 수행.
PG callback 멱등성 및 위변조 검증은 PG 도입 전까지 범위 외.
