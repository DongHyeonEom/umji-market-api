# 장바구니

## Endpoint

- `GET /api/cart`
- `POST /api/cart/items`
- `PATCH /api/cart/items/{itemId}`
- `DELETE /api/cart/items/{itemId}`

## 알고리즘 흐름

```mermaid
flowchart TD
    A[요청 계정 ID를 인증 subject에서 획득] --> B{작업}
    B -- 조회 --> C[장바구니 조회]
    C --> D{존재 여부}
    D -- 없음 --> E[빈 장바구니 반환]
    D -- 있음 --> F[항목·현재 SKU 정보 응답]
    B -- 항목 추가 --> G[SKU 조회]
    G --> H{SKU 판매 중}
    H -- 아니오 또는 없음 --> I[요청 거부 또는 미발견]
    H -- 예 --> J[장바구니 조회 또는 빈 상태 생성]
    J --> K{같은 SKU 항목 존재}
    K -- 예 --> L[기존 수량에 추가 수량 합산]
    K -- 아니오 --> M[신규 항목 추가]
    L --> N[장바구니 저장 및 응답]
    M --> N
    B -- 수량 변경 --> O[계정 장바구니와 항목 확인]
    B -- 항목 삭제 --> O
    O --> P{항목 소유 확인}
    P -- 실패 --> Q[미발견 오류]
    P -- 성공 --> R[수량 변경 또는 항목 제거]
    R --> S[장바구니 저장]
```

## 동작

- 활성 계정별 장바구니를 사용함.
  계정은 요청 본문이 아니라 인증 정보에서 조회.
- 항목은 SKU 기준으로 중복을 막고, 기존 SKU를 다시 추가하면 수량을 합산함.
- 판매 가능한 SKU만 추가할 수 있음.
- 장바구니 가격은 현재 카탈로그 가격이며 주문 가격을 확정하지 않음.
- 주문 생성 시 상품/SKU/가격을 주문 항목에 복사하고 재고를 예약한 뒤 장바구니를 초기화.

application UseCase는 장바구니 Port에 의존하고 JPA adapter가 저장 모델을 변환함.
